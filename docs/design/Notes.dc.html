RTL decisions and assumptions

RTL decisions

  • Logical CSS only. Use margin-inline, padding-inline, inset-inline-start, text-align: start/end and border-inline-end. One stylesheet serves both languages; the only RTL-specific rules are the font swap and the mirrored arrow.
  • Set direction on the root with <html lang="fa" dir="rtl">. Flex and grid then mirror by themselves: header, nav order, key-facts strip, stepper (− on the right, + on the left), radio cards, step numbers and the timeline columns.
  • Directional icons flip, others do not. Arrows and back chevrons get transform: scaleX(-1) in RTL. The “Why?” chevron points down, so it stays as is. Check marks, copy, print and the safety icons never flip.
  • Timeline. The time column sits at the start side (right in Farsi), then the rail, then the text. Time still reads top to bottom, earliest first. The rail stays vertical.
  • Numbers. Western digits (0–9) in both languages, so they match the kitchen scale and oven display. Quantity cells use tabular figures and align to the end side. Units are words in Farsi (“گرم”, “درجه”); the letter C is never used in Farsi text.
  • Latin names in Farsi. Style cards show the Farsi name, with the Latin name on its own line under it, forced dir="ltr". Inside running Farsi sentences, wrap Latin terms in <bdi> (the build can do this from a marker in the Markdown). No invisible characters.
  • Fonts. Vazirmatn for all Farsi text, headings in Vazirmatn 700. Line height 1.95 for Farsi body (Latin 1.65) so diacritics and ZWNJ forms do not collide.
  • Language switcher. Always in the header, each label in its own script and its own lang, so it looks the same in both directions. The link points to the same page in the other language.

Assumptions

  • All quantities, times and the “difficulty” and “fermentation” labels in these screens are placeholders so the layout can be judged. They are not recipe data. The real numbers come from recipes.json after the fact-check. The dough maths in the mockups (500 g of dough, 296.7 g of flour, 59.3 g of solution) uses placeholder percentages.
  • Farsi copy is a working draft for review against the Persian source guide; it follows the project rules (temperatures in words, short sentences, why next to each step).
  • Dark mode: on the real site it follows prefers-color-scheme with a manual override saved in localStorage. Here the boards switch it with data-theme.
  • Breakpoints: 640 px (two card columns), 768 px (inline nav), 900 px (calculator becomes two columns and the sticky summary bar hides), 1000 px (three card columns, style page splits into ingredients and steps).
  • Illustrations are flat inline SVG shapes (round, tray, square, deep) in five colours from the illustration tokens. No raster images.
  • Not drawn: loading states (static site), the empty state when no bake time is entered (the timeline then shows “hours before bake” instead of clock times), and the Farsi tablet view. They use the same components.
  • Print: black on white, no navigation, no shadows, tables and timeline kept together; the disclaimer is the last line. The style page prints the same way, with “Why?” text expanded.
